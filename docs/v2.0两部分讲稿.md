## 讲者 A：开场 + 玩法 + 评分（P1–P3）

> 约 3 分钟

---

**（P1）**

大家好，我们今天的项目是 **GeoGuessrEX**。

一句话概括：**用一组图片，讲述一段故事。**

这是一个基于 Google 街景的地理探索游戏。玩家看到一张街景画面，判断自己在哪，在地图上标记位置。接下来我们展开讲讲怎么玩、怎么算分。

---

**（P2）**

玩法叫"图寻挑战"。核心规则：

系统从已审核的公共题库**随机抽题**，玩家进入全屏街景画面，自由观察建筑、植被、路牌、语言等线索，**没有时间限制**。每局可选 3 题、5 题或 10 题。

提交猜测后，系统展示**双标记地图**——你的猜测位置和正确答案同时显示，中间用虚线连接。同时给出距离和单题得分。整局结束后有**结算面板**：总分、平均距离、最佳单题，还可以和历史成绩对比。成绩会写入个人统计，玩家可以选择分享到社区。

简单说就是：**抽题 → 看街景 → 找线索 → 标位置 → 看结果**，四步一次循环。

---

**（P3）**

刚才提到距离和得分，这里展开：核心是两个公式。

第一个，**Haversine 大圆距离公式**。输入玩家猜测的经纬度和正确答案的经纬度，计算球面最短距离，单位千米，地球半径取 6371 公里。

第二个，**指数衰减得分公式**。满分 5000 分。距离越近分越高，猜对位置直接 5000 满分。指数衰减的好处是远端也有区分度——不会说稍微猜远一点就零分了。

代码里就是一行：`5000 × e^(-距离/2000)`。距离 0 公里满分，2000 公里约 1840 分，然后逐渐趋近于零。

---

好，基本玩法和评分机制就介绍到这里。下面请讲者 B 介绍 v2.0 的新功能，并带来现场演示。

## 讲者 B（兼演示）：社交 + 管理后台 + 架构 + 演示 + 规划（P4–P9）

> 约 5–6 分钟

---

**（P4）**

我先介绍 v2.0 新增的**社交功能**。

首先是**好友系统**：玩家可以通过昵称或用户 ID 搜索其他用户，发送好友申请，对方收到站内通知后选择同意或拒绝。好友列表展示头像、昵称、最近活跃时间和统计数据摘要。

然后是**社区动态**：完成一局游戏后，玩家可以点击"分享战绩"，系统生成一张战绩卡片——包含题目截图、得分、距离和排名百分比，玩家还可以加上文字感言。动态发布后会出现在全站动态流中，其他玩家可以点赞和评论。

---

**（P5）**

接着说 v2.0 的另一个重要模块：**Web 管理后台**。这是一个独立前端应用，只有管理员和审核员可以访问。有四个模块：

**题库管理**：审核队列按提交时间排序，审核员可以预览题目并一键通过或驳回，支持批量操作。题库列表支持按状态、类型、上传者、标签进行筛选。

**用户管理**：用户列表支持搜索和角色筛选，管理员可以查看用户详情、统计数据、最近活动，支持封禁/解封以及角色分配——普通用户、审核员、管理员三个角色。

**数据统计**：平台概览展示总用户数、总题目数、今日局数。还有题库统计、用户趋势和题目排行。

**系统配置**：限时挑战倒计时、游客每日局数、评分参数等都可以在后台直接调整，不需要改代码。

---

**（P6）**

说完功能，简单过一下**系统架构**。三层结构：

数据层：题库和用户数据通过数据库存储。后端：Express 框架，PBKDF2 密码加密，完整的 CRUD API。前端：Vite + React 18，高德地图 JSAPI 做地图交互，Google Maps Embed API 加载街景。

整体是前端 → 后端 → 存储三层架构，Bearer Token 贯穿整个认证链路。

---

**（P7 + 现场演示）**

好，大家看屏幕。这是游戏的实际界面——**复盘阶段**的结果页。左边是结果地图，绿色标记是猜测位置，红色是正确答案，虚线连线展示偏差。右边是结果面板，显示距离、得分、坐标和地点介绍。

**【切换到浏览器，开始现场演示】**

下面我给大家实际演示完整流程。

打开浏览器，登录后进入首页。选择一个题库组，点击"开始答题"。

现在进入了全屏街景画面——这是 Google 街景的 360° 全景图。左上角 HUD 显示玩家信息、题库组名称、题目进度和状态。右下角是折叠小地图。

我点击"展开地图"，高德地图出来了。我现在根据街景里的线索——路牌、建筑风格、植被——判断位置，然后在地图上点击放置标记。

放好标记后，点击"提交答案"。

好，现在进入了结果页。左边是双标记地图，绿色是我的猜测，红色是正确答案，中间虚线是偏差。右边卡片显示距离、得分、坐标和地点介绍。点击"下一题"继续。

这就是完整流程：**看街景 → 找线索 → 标位置 → 看结果**。

（演示结束）

**（P8）**

最后是**未来规划**，分三个阶段：

**Phase 1**：完善核心体验——扩充题库、优化移动端交互、增加音效和动画。

**Phase 2**：多人对战——实时房间、排行榜、WebSocket 推送。

**Phase 3**：商业化探索——会员订阅、广告位、自定义题库付费功能。

MVP 已经验证通过，核心玩法可行。v2.0 补齐了用户体系和社交能力，具备向完整产品演进的扎实基础。
