## 讲者 A：开场 + 基本玩法（P1–P2）

> 约 2 分钟

---

（P1）

大家好，我们今天汇报的项目是 **GeoGuessrEX**。

一句话概括：**用一组图片，讲述一段故事。**

这是一个基于 Google 街景的地理探索游戏。你看到一张街景画面，判断自己在地球上的位置，然后在地图上标记。听起来简单，但背后的技术栈和功能设计，我们想借这个机会跟大家分享。

（P2）

先看基本玩法——我们称之为**"图寻挑战"**。

核心流程是：系统从已审核的公共题库中随机抽题，玩家进入全屏街景画面，自由观察建筑、植被、路牌、语言等各种线索，没有时间限制。每局可以选择 3 题、5 题或 10 题。

提交猜测后，系统展示一张双标记地图——你的猜测位置和正确答案同时显示，中间有连线。同时给出距离和单题得分。整局结束后有结算面板，展示总分、平均距离、最佳单题，还可以和历史成绩做对比。成绩写入个人统计，玩家可以选择分享到社区。

基本玩法就介绍到这里。下面请讲者 B 来讲评分怎么算、系统怎么搭。

## 讲者 B：评分机制 + 系统架构（P3, P6）

> 约 2 分钟

---

（P3）

刚才 A 提到了距离和得分，我来展开讲：**距离怎么换算为得分？**

核心是两个公式。第一个是 **Haversine 大圆距离公式**——输入玩家猜测的经纬度和正确答案的经纬度，计算球面最短距离，单位是千米。

第二个是**指数衰减得分公式**。满分 5000 分。当你的猜测距离答案 0 公里时得满分 5000。距离越远分数越低，但指数衰减保证远端也有区分度，不会出现猜远了一点就零分的情况。这个函数在我们代码里就一行：`maxScore * Math.exp(-distanceKm / decay)`，满分 5000，衰减常数 2000 公里。

（P6）

再说系统架构。三层结构：

**数据层**：题库和用户数据通过数据库存储，告别了 v1.0 的纯 JSON 文件方案。

**后端**：Express 框架，PBKDF2 密码加密认证，完整的 CRUD API，Haversine 评分逻辑。

**前端**：Vite + React 18，高德地图 JSAPI 做猜点和结果展示，Google Maps Embed API 加载街景，Leaflet 作为备用地图。

整体是前端 → 后端 → 存储三层架构，Bearer Token 贯穿整个认证链路。

架构就介绍到这里。接下来请讲者 C 带来实际演示。

## 讲者 C（演示者）：社交功能 + 现场演示（P4, P7 + Live Demo）

> 约 3 分钟

---

（P4）

在演示之前，我先快速介绍一下 v2.0 新增的**社交功能**。

首先是**好友系统**：玩家可以通过昵称或用户 ID 搜索其他用户，发送好友申请，对方收到站内通知后选择同意或拒绝。好友列表展示头像、昵称、最近活跃时间和统计数据摘要。

然后是**社区动态**：完成一局游戏后，玩家可以点击"分享战绩"，系统生成一张战绩卡片——包含题目截图、得分、距离和排名百分比，玩家还可以加上文字感言。动态发布后会出现在全站动态流中，其他玩家可以点赞和评论。

（P7）

好，大家看屏幕。这是游戏的实际界面——**复盘阶段**的结果页。

左边是结果地图：绿色标记是玩家的猜测位置，红色标记是正确答案，虚线连线直观展示偏差。右边是结果面板：显示距离、得分、正确坐标和地点介绍。

**（切换到浏览器，开始现场演示）**

下面我给大家实际演示一遍完整流程。

首先打开浏览器，访问 localhost:5173。登录后进入首页，选择一个题库组，点击"开始答题"。

现在进入了全屏街景画面——大家可以看到这是 Google 街景的 360° 全景图。左上角 HUD 显示玩家信息、题库组名称、当前题目进度和状态。右下角是折叠小地图。

我点击"展开地图"，高德地图出来了。我现在根据街景里的线索——比如这个路牌的语言、建筑的风格——判断这是哪里，然后在地图上点击一个位置，放一个绿色标记。

放好标记后，点击"提交答案"。

好，现在进入了结果页。左边是双标记地图，绿色是我的猜测，红色是正确答案，中间的虚线是偏差距离。右边显示结果数据——距离、得分、坐标，下面是地点介绍。点击"下一题"就可以继续。

这就是完整的游戏流程：**看街景 → 找线索 → 标位置 → 看结果**，四步一次循环。

（演示结束）

## 讲者 D：管理后台 + 未来规划（P5, P8）

> 约 2 分钟

---

（P5）

我来收尾，介绍 v2.0 的**管理后台**和接下来的计划。

管理后台是一个独立的前端应用，只有管理员和审核员可以访问。主要包括四个模块：

**题库管理**：审核队列按提交时间排序，审核员可以预览题目内容并一键通过或驳回。支持批量操作——勾选多道题目一次性处理。题库列表支持按状态、类型、上传者、标签进行筛选。

**用户管理**：用户列表支持搜索和按角色筛选，管理员可以查看用户详情、统计数据、最近活动。支持封禁和解封操作，以及角色分配——普通用户、审核员、管理员三个角色。

**数据统计**：平台概览——总用户数、总题目数、今日游戏局数。题库统计——待审、通过、驳回的题目数量和审核通过率。用户趋势——日新增注册和日活。题目排行——被答题最多的题目和平均得分最高的题目。

**系统配置**：限时挑战倒计时、游客每日局数、评分参数等都可以在后台直接调整，不需要改代码。

（P8）

最后是**未来规划**，分三个阶段：

**Phase 1**：完善核心体验——扩充题库、优化移动端交互、增加音效和动画。

**Phase 2**：多人对战——实时房间、排行榜、WebSocket 推送。

**Phase 3**：商业化探索——会员订阅、广告位、自定义题库付费功能。

MVP 已经验证通过，核心玩法可行。v2.0 补齐了用户体系和社交能力，具备向完整产品演进的扎实基础。
